# Исправления tutor-bot (напоминания, «Мои занятия», DND, оплата)

## Обновление v3 (userbot не принимает другие номера)

**Проблема:** нельзя привязать другой аккаунт репетитора (напр. US-номер)
для рассылок «от моего имени».

**Причины:**
1. `«🔌 Отключить»` закрывало только соединение, но **файл сессии
   `data/tutor_userbot_session.*` оставался** с авторизацией старого
   аккаунта. Telethon по-прежнему «считал» себя в другом аккаунте →
   запрос кода / вход на новый номер падали; после перезапуска бота
   старый аккаунт подключался обратно сам.
2. Ошибки скрывались: бот показывал только «❌ Ошибка отправки кода»
   или «❌ Неверный код», реальная причина (2FA, флуд-веит, BAN) не видна.
3. Двухступенчатый пароль (2FA) не обрабатывался — такой аккаунт
   вообще не мог войти.

**Что изменено:**
- `services/userbot.py` — новый метод `reset_session()` (удаляет файл
  сессии); `send_code_request()`/`sign_in()` теперь возвращают
  `(ok, текст_ошибки)`; при смене номера старая сессия сбрасывается
  автоматически; новая `finish_2fa()` для пароля 2FA; нормализация
  номера (можно вводить и без «+»).
- `handlers/admin.py` — новая кнопка **«🔄 Сменить аккаунт»** в меню
  userbot (с подтверждением); «🔌 Отключить» теперь тоже удаляет
  сессию; все шаги авторизации показывают настоящую причину ошибки;
  новый шаг ввода пароля 2FA.

**Как теперь сменить номер:** /admin → Рассылки → Userbot →
«🔄 Сменить аккаунт» → «✅ Да, отвязать и сменить» → ввести новый номер
(+15551234567 и т.п.) → код → (если есть) пароль 2FA.

Файлы v3: `services/userbot.py`, `handlers/admin.py`.

| Проблема | Корневая причина | Что изменено |

На подсказках ввода теперь есть инлайн-кнопка «❌ Отмена» |

Файлы v2: `database.py`, `handlers/fixes.py`, `tests/smoke_test.py`
(тест вырос до 23 проверок).


## Что было не так — причины

| Проблема | Корневая причина в коде |
|---|---|
| Записи «исчезали» из «📋 Мои занятия», хотя в админке были | Новые записи создаются со статусом `pending`, а меню ученика (и список в `fixes.py`) фильтровало только `status='confirmed'`. При этом **в боте нигде не было действия, переводящего запись в `confirmed`** — поэтому у ученика список всегда был пуст |
| Бот не напоминал ученикам и репетитору | `get_upcoming_bookings()` искал только `status='confirmed'` → напоминания не могли отправиться вообще никогда. Плюс время окна считалось `datetime.now()` (на хостинге это **UTC**, а слоты в МСК → сдвиг на 3 часа). Плюс один общий флаг `reminder_sent` блокировал второе напоминание (за 15 минут) после первого (за 60) |
| Кнопки DND «не работали» | (а) Окно DND проверялось по серверному времени (UTC), а не по `TIMEZONE` из `.env` — с 09:00 до 11:59 МСК DND не срабатывал, а после 21:00 ещё час «зависал»; (б) в `admin_dnd_enable/disable` была сломанная конструкция из двух строк, из-за которой кнопка «Назад» не появлялась и текст был неполным |
| «✅ Я оплатил» — репетитор не видел оплату нормально | Нажатие **не меняло статус счёта** — он оставался `pending` вечно: бот каждый день повторно слал ученику «напоминание об оплате», счёт не закрывался в статистике. Уведомление репетитору было однострочным, без имени ученика |

## Изменённые файлы (скопируйте их в свой проект)

```
database.py                 — ядро исправлений (см. ниже)
services/notification.py    — помечает конкретное напоминание (60/15 мин), дата в тексте
utils/helpers.py            — новая функция visible_bookings()
handlers/student.py         — «📋 Мои занятия»: все активные записи
handlers/fixes.py           — «mybookings:list», «✅ Я оплатил» (новый статус + уведомление
                              репетитору с деталями), список «⏳ Ожидают оплаты» в админке
handlers/admin.py           — кнопки DND «Включить/Выключить»
handlers/payments.py        — меню «💳 Оплата» ученика (виден статус «оплата сообщена»),
                              «отметить оплаченным» — теперь только для админа +
                              уведомление ученику «Оплата подтверждена!»
tests/smoke_test.py         — новый: автотест всех исправлений (19 проверок)
```

### Что именно в `database.py`
- `get_upcoming_bookings()` — время теперь из `TIMEZONE` (`.env`), записи `pending` **и** `confirmed`, каждое напоминание из `REMINDER_BEFORE_MINUTES` отправляется ровно один раз (новая колонка `reminders_sent`, JSON-список; старые данные с флагом `reminder_sent` поддерживаются)
- `mark_reminder_sent(id, minutes)` — запоминает, какое именно напоминание ушло
- `get_today_bookings()` — таймзона из `.env` + учитывает `pending` (иначе утренняя сводка пустая)
- `is_dnd_active()` — таймзона из `.env`
- `get_payment_by_id()` — теперь возвращает имя/юзернейм ученика (нужно для уведомления)
- **новые** `report_payment_paid()` и `get_reported_payments()` — статус счёта `reported`
- миграция сама добавит колонку `reminders_sent` при старте
- уникальный индекс: нельзя создать две **активные** записи на один слот (защита от гонок при записи)

### Новый контур оплаты
```
ученик: [Я оплатил]
  → счёт: pending → reported
  → репетитору в Telegram: «Ученик сообщил об оплате! Имя, сумма, описание, № счёта»
  → ученику: «Оплата сообщена, ждём подтверждения»
  → бот больше НЕ спамит этому счёту напоминаниями об оплате

репетитор: /admin → Оплаты → «⏳ Ожидают оплаты»
  → видно два блока: обычные pending и 🔔 «ученик оплатил»
  → [✅ Подтвердить] → счёт: paid, ученику: «🎉 Оплата подтверждена!»
```

## Как развернуть

1. Скопируйте 7 изменённых файлов в свой проект (пути те же).
2. Перезапустите бота (на Heroku — `git push`; локально — перезапуск процесса).
3. Колонка `reminders_sent` добавится автоматически при старте, БД не трогайте.
4. Убедитесь, что в `.env` `TIMEZONE` совпадает с часовым поясом, в котором
   вы ставите слоты (обычно `Europe/Moscow`).
5. Проверить логику можно без запуска бота:
   ```bash
   python3 tests/smoke_test.py
   # → ✅ ВСЕ 19 ПРОВЕРОК ПРОЙДЕНО
   ```

## Что осталось на ваше усмотрение
- Если хотите, чтобы у записи был реальный статус «подтверждено» (✅),
  добавьте в карточку ученика в админке кнопку «Подтвердить запись»
  (`UPDATE bookings SET status='confirmed' WHERE id=?`) — после этого
  ученик тоже увидит ✅. Напоминания с этим не зависят: они уходят и для pending.
- Валидация: тесты проверяют только слой БД/логики; прогоните живой сценарий
  «запись → напоминание через 60 и 15 мин → «Я оплатил» → подтверждение».
